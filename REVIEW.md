# Правила ревью

## Что проверять по существу

### Граница контрактов

`packages/shared` — хребет проекта. Схема zod объявляется там, оба приложения используют её.

- Схема, нужная обоим приложениям, живёт в `packages/shared`, а не в `apps/backend`.
- Рукописных интерфейсов, дублирующих контракт, быть не должно ни на одной стороне.
- Бэкенд валидирует через схему; фронтенд **кастует** (`as SomeDto`) и не парсит повторно —
  ответ уже провалидирован на бэкенде (`@ZodResponse` + глобальный `ZodValidationPipe`).
- Фронтовый zod допустим только для пользовательского ввода, которого бэкенд ещё не видел:
  `zodResolver` в `features/auth-*/model/schema.ts` поверх общей схемы.

### Backend: CQRS

Фича — это репозиторий плюс хендлеры. Сервисного слоя на фичу нет.

- Никаких `<feature>.service.ts` внутри фич-модуля. Логика — в хендлерах команд и запросов,
  cross-cutting машинерия — модулем в `src/shared/` (образец — `CryptoModule` → `PasswordHasherService`).
- Команды и запросы несут тип результата: наследуют `Command<T>`/`Query<T>` и вызывают `super()`.
  Тогда `execute(new GetUserByIdQuery(id))` обходится без аргументов-типов.
- Репозитории возвращают сгенерированные типы Prisma. Форма строки со связями —
  `Prisma.XGetPayload<{ include: … }>`, экспортируемая из репозитория.
- Конвертация в wire-DTO (`Decimal` → `number`, `Date` → ISO) — работа контроллера
  (`toDto` в `transaction.controller.ts`). Хендлеры пропускают строки как есть.
- Инжектируемые параметры конструктора импортируются как **значения**: `import { Foo }`,
  никогда `import { type Foo }` — иначе метаданные декораторов теряются и DI ломается в рантайме.

### Backend: владение данными

**Самое дорогое место в ревью.** Каждый user-scoped запрос фильтруется по `userId` внутри
самого запроса: `findByIdForUser(id, userId)`, а не `findById(id)` с проверкой после загрузки.

Это касается и мутаций: `update` и `delete` с `where: { id }` — нарушение, даже если
вызывающий хендлер делает пред-проверку. Защита, которая держится на дисциплине вызывающего
кода, ломается молча и с межпользовательской записью. Скоупить нужно в запросе:
`updateMany`/`deleteMany` с `where: { id, userId }` и трактовкой `count === 0` как «не найдено».

### Backend: DTO

- Каждый DTO-класс — однострочник `extends createZodDto(схема из packages/shared)`.
- Контроллер принимает эти классы в `@Body()`/`@Query()`, возвращаемый тип аннотирует общим
  _типом_, сериализацию и OpenAPI вешает через `@ZodResponse({ type: XDtoClass })`.
- Query-параметры приходят строками, поэтому query-схемы используют `z.coerce` с `.default()` —
  контроллер не должен видеть `undefined` для `page`/`limit`.

### Frontend: FSD

Слои: `app → _pages → widgets → features → entities → shared`.

- Импорты идут **только вниз**; слайсы одного слоя не импортируют друг друга.
- Публичная поверхность слайса — его `index.ts`.
- Исключение, которое надо знать: серверные модули намеренно **не** забаррелены и импортируются
  глубоким путём — `@/shared/auth/refresh.ts`, `@/shared/api/server-fetch.ts` и `api/*.ts` каждой
  сущности. Так клиентский компонент не утащит их в браузерный бандл через чужой barrel.
- Новый слайс в `widgets` — только если им реально пользуется больше одной страницы. Компонент
  одной страницы живёт в её собственном `_pages/*/ui/`.
- Route Handlers в `app/api/auth/*/route.ts` содержат полную реализацию, а не реэкспорт.

### Frontend: auth и поток данных

- Токены живут только в httpOnly-куках и никогда не попадают в JS. С auth-эндпоинтами бэкенда
  общается только `app/api/auth/*`; тело ответа токенов не содержит.
- Обновление токена имеет ровно одну реализацию — `POST /api/auth/refresh`. Ни Server Component,
  ни `serverFetch` не обновляют токен: `cookies()` там read-only, и обновление отозвало бы старый
  токен, не сохранив новый.
- Новый защищённый маршрут добавляется **и** в `PROTECTED_PATHS`, **и** в матчер `proxy.ts` —
  они синхронизируются руками, вывести одно из другого нельзя. Пропущенный в матчере маршрут
  начинает отдавать 401, когда токен протухнет.
- Server Component ходит за данными через `api/*.ts` сущности, тот — через `serverFetch`.
  Решение о редиректе принимает вызывающий код, а не слой запроса.

## Чек-лист

### Backend

- [ ] Нет `<feature>.service.ts` внутри фич-модуля; cross-cutting вынесено в `src/shared/`
- [ ] Команды/запросы наследуют `Command<T>`/`Query<T>` и вызывают `super()`
- [ ] Репозитории возвращают сгенерированные типы Prisma; связи — через `Prisma.XGetPayload<…>`
- [ ] **Каждый user-scoped запрос, включая `update`/`delete`, фильтрует по `userId` в самом запросе**
- [ ] Конвертация `Decimal` → `number` и `Date` → ISO — в контроллере, не в хендлере
- [ ] DTO — однострочник `extends createZodDto(схема из packages/shared)`
- [ ] Инжектируемые зависимости импортируются как **значения**, не `import { type … }`
- [ ] Query-схемы используют `z.coerce` с `.default()`
- [ ] Импорт клиента Prisma из `../generated/prisma/client`, не из `@prisma/client`
- [ ] Структура модуля: контроллер, репозиторий, `commands/`, `queries/`, `dto/`,
      хендлеры в `commands|queries/handlers/`

### Frontend

- [ ] Импорты идут только вниз по `app → _pages → widgets → features → entities → shared`
- [ ] Слайсы одного слоя не импортируют друг друга
- [ ] Публичная поверхность слайса — `index.ts`; глубокие импорты только для серверных модулей
- [ ] Ответы бэкенда **кастуются** (`as DTO`), а не парсятся повторно через zod
- [ ] Фронтовый zod — только для пользовательского ввода в `features/auth-*/model/schema.ts`
- [ ] Новый защищённый маршрут добавлен **и** в `PROTECTED_PATHS`, **и** в матчер `proxy.ts`
- [ ] Токены не покидают httpOnly-куки; обращения к auth-эндпоинтам только из `app/api/auth/*`
- [ ] Новый `widgets`-слайс добавляется, только если им пользуется больше одной страницы
- [ ] Нет рукописных интерфейсов, дублирующих контракты из `packages/shared`
- [ ] Токены темы правятся в `src/app/styles/globals.css`; `@media (prefers-color-scheme: dark)`
      не возвращается — тёмная тема классовая

### Общее

- [ ] `pnpm typecheck` проходит
- [ ] `pnpm lint` проходит
- [ ] Общие схемы лежат в `packages/shared`, а не продублированы в приложении
- [ ] После правок в `packages/shared/src` при запущенном `pnpm dev` пакет пересобран вручную
- [ ] Не сломаны задокументированные решения: пины версий, `_pages`/`_app`, `proxy.ts`,
      `moduleFormat = "cjs"`, `PrismaService` без `extends`
- [ ] Новые зависимости оправданы задачей
- [ ] Коммиты и заголовок PR — по Conventional Commits
- [ ] В теле PR есть **Summary** и **Test plan**
- [ ] Затронутые `CLAUDE.md`/`README.md` обновлены вместе с кодом

> `pnpm test` / `pnpm test:e2e` падают — это ожидаемо, а не регрессия
> (генератор Prisma отдаёт `.ts` с `.js`-спецификаторами, Jest их не резолвит).
